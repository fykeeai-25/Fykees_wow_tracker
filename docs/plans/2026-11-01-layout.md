# Dashboard Layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Replace tabs with a three-column dashboard (characters | bubbles | search).
**Architecture:** App owns `selectedKey` and `searchOpen`; `CharacterList`, `Dashboard` (bubble registry with Summary/Detail components) and `ItemSearch` are siblings in a CSS grid; the old `ProfessionsView` splits into `ProfessionsSummary` and `ProfessionsDetail` (character passed in).
**Spec:** `docs/specs/2026-11-01-layout-design.md`

## Global Constraints
- Copy exactly as in the spec; no OS notifications; existing tests for professions/materials keep their assertions (only render entry points change).
- Breakpoint 1000 px for hiding the search column; window minWidth stays 640.

## Review Focus
1. Selected character removed by a new snapshot → fall back to the first character. Test in Task 2.
2. Character without professions → Professions bubble says `No professions yet.` Test in Task 2.
3. Full view open and character changes → full view stays on the same bubble for the new character. Test in Task 2.
4. No currencies at all → info line has no currency part. Test in Task 1.
5. Unknown currency name → initials (`Honor Points` → `HP`). Test in Task 1.
